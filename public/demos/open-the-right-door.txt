Apply the repair
$ cat <<'YAML' | kubectl apply -f -
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: notes-ingress
  namespace: quest
spec:
  podSelector:
    matchLabels: {app: little-notes}
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector:
            matchLabels: {role: frontend}
        - namespaceSelector:
            matchLabels: {kubernetes.io/metadata.name: kube-system}
      ports: [{protocol: TCP, port: 80}]
YAML
kubectl patch ingress notes -n quest --type=json -p '[{"op":"replace","path":"/spec/rules/0/http/paths/0/backend/service/name","value":"notes"}]'
kubectl exec probe -n quest -- wget -qO- -T 3 http://notes

Run behavioral checks

PASS Ingress isolation configured — Apply an ingress policy to the notes Pods.
PASS Frontend allowed; intruder blocked — Test from two real Pods; a broken Service alone must not pass.
PASS Correct Ingress route — Route notes.quest.test to notes:80.
PASS Ingress responds — Send a Host-header request to the ingress controller.

Why the repair works
The policy makes the destination Pods ingress-isolated and permits specific sources. The Service still routes requests, while Ingress adds an HTTP host rule. A real connectivity test catches policies that look plausible but do not enforce the intended access.
